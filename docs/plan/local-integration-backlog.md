### LIN-004 接入账本、迁移与事务 outbox

- **主责/范围**：数据/接入后端；`packages/integrations/src/node/{store,migrate,outbox}.ts`、`src/node/migrations/` 和真实 PG 测试；精确表、键和索引以契约文档为准。

- **先失败测试**：并发重复提交、同 operationId 不同摘要、事务中途失败、跨租户 FK、旧 fence 写回、迁移 checksum 变化。

### LIN-005 共享素材服务与接入传输适配

- **主责/范围**：媒体/存储负责人；缺失共享服务时默认新建 `packages/storage/src/{store,local,transfer}.ts` 与 `services/media-py/app/{probe,images}.py` 及对应测试；接入边界放 `integrations/src/contracts/transfer.ts` 及对应 adapter，Bridge staging 由 012 装配。若原任务已交付同职责模块，在 readiness 记录实际路径和端口映射后直接复用，不为符合目录名再造一套服务。
- **依赖/产物**：001；共享子项实现授权读取、暂存、流式写入、SHA-256、图片解码/ffprobe、原子发布、完整性状态与回收；集成子项只实现 operation/输出槽位到共享对象的映射及受限传输会话。
- **先失败测试**：错误哈希、截断文件、超额上传、目录/reparse point 越界、假 MIME、存储成功但数据库提交失败、磁盘满；prepare 前输入上传被错误要求已有 operation，设备伪装人类进入无 operation 输入分支。
- **验收**：`LIN-005-A` 校验失败从不出现 ready 素材；`LIN-005-B` 大于 64 MiB 的受控文件不全量 base64/内存缓冲，实测内存随块大小受限；`LIN-005-C` orphan 可重试归档或按引用回收；`LIN-005-D` 同哈希跨项目不泄漏访问权；`LIN-005-E` 项目输入按用途授权后可在 prepare 前封存并取得引用，生成输出仍强制 operation/槽位/执行授权，输入素材经过候选采用才能成为正式参考版本。
- **证据/PR/估算**：PR-05a 共享 6–9 人日，PR-05b 集成 2–3 人日；已有 P-ASSET 验收则 05a 为 0。保存文件 manifest、错误矩阵、内存/临时文件观察；不得把通用服务再次列入 009 开发工时。

### LIN-006 共享授权应用服务与连接管理

## 9. 实施启动与完成证据

实施负责人在获准开始开发后按以下顺序操作；本文本身不创建自动化或后台观察任务：

1. 读取当前 `AGENTS.md`、本方案/契约、原阶段进展和 `git status`。记录基线 commit/未提交变更，明确文件责任；保留其他任务改动。若同一文件正在修改，先约定接口/顺序，不覆盖。
2. 建立 `docs/validation/local-integrations/readiness.md`（实施时创建），逐门记录 `READY / PARTIAL / BLOCKED`、证据路径、版本、责任人、下一动作。不得默认把全部门设为 READY。
3. 把满足依赖的 LIN 子任务挂到原计划对应任务，默认先启动 001/002/003；没有实机时可启动 001 和符合门条件的 004/005/006/007/013 mock 部分。实机任务保持证据未完成。
4. 每个 PR 先加入上文对应失败测试，观察失败原因后实现；运行受影响包检查。涉及数据库/租约/权限要运行真实 PG/进程负测。跨域里程碑运行根 `pnpm check`，不为纯文档反复跑全套代码测试。
5. 发布或真生成前核对 task/operation 归属、权限、模型/工作区、费用授权和实机版本。未知外部行为进入 LIN-002/003/020 的证据任务，不填入猜测参数。
6. 每项仅在验收 ID 全部通过、对应审查发现关闭、证据可复现后标完成。若接口 mock 已完而实机未验，标 `implementation_done / real_acceptance_pending`，不得写整个任务完成。

统一完成证据至少包含：`LIN-xxx`、实现版本/PR或工作区基线、协议/schema/模式 pin、测试命令和退出结果、验收 ID 与证据位置、真实/合成标签、输出文件哈希（如适用）、审查结论、剩余限制与环境阻塞。证据中不得含凭据；真实数据使用获授权测试素材。

现有可直接复用的检查入口为 `pnpm check`、各包 `test/typecheck/test:coverage` 和根 `test:durable:local`、`test:versioning:local`、`test:agents:local`、`test:access:local`、`test:server:local`。新包脚本及 `test:integrations:local` 由 001/004 实现后才能执行；不把建议命令当作已存在脚本。

## 10. 暂停、恢复与回滚

| 触发 | 立即动作 | 恢复条件 |
|---|---|---|
| 前置 API/schema 变更 | 暂停受影响 PR，保留其他独立工作 | 契约测试和兼容映射修正，重新 pin |
| 实机环境/凭据缺失 | 暂停真实验收，继续明确标记的 mock/纯域任务 | 对应 E-COMFY/E-BEEF 证据补齐 |
| 提交结果未知 | 停止新提交原操作，保留预算和记录，进入对账 | 远端证据确认或人工明确建立新尝试；绝不将超时当未受理 |
| 双向冲突/外部 schema 变化 | 停止该画布后续写入，保存已完成检查点 | 新 revision/基线计划与新 operationId 经验证 |
| 发布/镜像构建环境错误 | 停止发行，保留上一可用版本 | 固定依赖构建与真实部署通过，不跳过校验 |
| 运行时回滚 | 先关闭新派发，保留查询/对账/收回文件；排空可安全结束的任务 | 旧版本能解释所有在途协议/模式，否则保留兼容执行器并暂停不兼容任务 |

数据库默认采用向前兼容的增量迁移：先加结构、再部署读取兼容代码、最后启用写入；回滚关闭功能/回退应用，不在线删除在途 operation、回执、预算和外部绑定。破坏性清理是单独维护动作，需备份和显式授权，不能作为发布失败的自动补偿。BeefTV 已成功的用户可见写入不自动撤销；同步回滚通过新计划和可审阅候选处理。
