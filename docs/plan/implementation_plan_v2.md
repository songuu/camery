## 1. 系统架构

### 1.1 分层

```
┌ 输入 ──── 小说分批导入 · 剧本导入 · 设计稿/分镜表导入 ·（工坊）图书与笔记
├ 情报 ──── 外部采集器 → HTTP / MCP / 文件 → 原始观测 → 归并 → 每日简报 / 反同质化
├ 理解 ──── StoryBible（人物/关系/伏笔）·（工坊）ClaimGraph
├ 开发 ──── 改编五件套附题材配方 · 结构化分集地图 · 立项成本画像 · 剧本圣经
├ 剧本 ──── Episode → Scene → Beat → Line · 台词本 · 合规预审
├ 锚点 ──── 角色 / 场景 / 道具 / 画风 / 声音（版本 · 派生 · 失效追踪）
├ ★分镜 ─── 导演阐述 · 站位/机位图 · 镜头 ← 取用 → 素材段 · 首尾/多关键帧 · 可拍性
├ 预演 ──── 声音先行 · 动态分镜 · 成本预估 · 预算闸门 · 混合档位
├ 出片 ──── 模型模式 · 生成队列 · 通告单排产 · 接戏链 · 漫剧渲染 · 手动替换
├ 选片 ──── 选片台 · 粗剪预览 · 镜头档案 · 数据飞轮
└ 交付 ──── 剪映草稿 · FCPXML / EDL / OTIO · 分轨 / 字幕 · 分镜册 · 备案材料包
            （工坊：五种成品 + 发布中心）

编排：AI 剧组 —— 制片调度 → 角色 Agent 产出候选 → 场记/审片回路 → 人工闸门
横切：持久化执行（PostgreSQL）· 模型模式注册表 · 方法包 · 版本内核 · 成本引擎
      · 协作与权限 · 授权 · 审计
```

### 1.2 部署形态

**私有化（Studio 1.0）**

```
[浏览器] ──HTTPS──► [app 容器：api + worker + 前端静态资源]
                        │                    │
              [PostgreSQL + pgvector]   [media-py 容器：文档解析 / OCR / FFmpeg / 音频分析]
                        │
              [存储：本地磁盘 / NAS，或 MinIO]

客户自备（外部）：ComfyUI 节点（本机 / 局域网 / 租用 GPU）· 中转或官方模型 API · OpenAI 兼容 LLM
```

- 一台 Linux 服务器 + Docker Compose 即可运行；应用服务器不需要 GPU。
- 支持内网离线安装；扩容时增加 worker 容器（同一镜像，按角色启动）。

**云端（知识工坊 1.0，阶段 5 引入）**：多租户、S3/OSS、横向扩展的 worker 池、点数计费、平台提供的已备案模型；工坊需要的模板渲染（无头 Chromium）作为独立容器加入。

## 3. 数据模型：IR v0.5（v2.1 规划扩展）

### 3.1 原则

1. 数据库是正式状态；JSON 分镜包只是导出快照。
2. 稳定 ID 用 ULID；显示编号（镜号）单独存，可随时重排。
3. 时间相对化：每集从 0 计时；画面轨只存顺序键 + 时长，开始时间推算；声音锚定到镜头/节拍/其他 cue。
4. 不存冗余：覆盖关系是计算视图；cue 的文本和说话人从台词推出。
5. 一切修改都是 ChangeSet：用户编辑、Agent 产出、外部替换走同一机制。

### 3.2 实体

| 域 | 实体 |
|---|---|
| 项目 | Project（mode、content_kind、rights_status、锁定的内容包版本） |
| 来源 | Source、SourceSnapshot、SourceSection、NoteItem（工坊） |
| 故事库 | Character、Location、Prop、Relationship、PlotThread（伏笔/揭示）、KnowledgeState（谁在何时知道什么） |
| 连续性 | EpisodeStateSnapshot（事实、知情、位置/造型/持物、伏笔、来源版本、影响范围）；下集生成读取上集已采用快照 |
| 知识图（工坊） | Concept、Claim、Evidence、ClaimDependency |
| 开发 | AdaptationPlan（含题材配方与抽离测试）、EpisodePlan（open_hook_type、cliffhanger_type、emotion_intensity、付费卡点）、PlotUnit（跨集情节单元）、GenreProfile（节奏/禁忌/视觉指纹）、AdaptationDecision、ShootabilityProfile（场景/人物/造型/高风险元素与成本区间） |
| 剧本 | Episode、SceneOccurrence、Beat、DialogueLine、OnScreenText |
| 锚点 | Anchor（kind：character/set/prop/style/voice/host）、AnchorVersion、DerivedView、AppearanceVariant（适用集段）、SetVariant（时段/天气/状态）、VoiceProfile（情绪变体、多音字词典、授权记录）、CastingSession（候选） |
| 导演 | DirectorPlan、BlockingPlan、CameraPlacement（俯视图上的位置与朝向） |
| 分镜 | Rendition、Segment、Shot、ShotTake（取用与替代候选）、Keyframe、KeyframeCandidate、AudioTrack、AudioCue、DiagramSpec（工坊） |
| 版本 | ObjectRevision、ChangeSet、AdoptionRecord、Lock |
| 出片 | ModelMode、ModelConnection、GenerationJob、Attempt、MediaAsset、CallSheetBatch、ContinuityLink |
| 选片 | DailiesDecision（accepted / rejected / retake / trim_usable / needs_patch + 原因码、问题时间点、下一步）、ShotDossier（视图） |
| 成本 | CostEstimate、Budget、CostLedgerEntry |
| 交付 | ExportJob、FilingPackage、RightsRecord（音乐/字体/音效/声音授权编号与适用范围）、LabelVerification（规则版本、检查结果）、Release / PublishIntent / PublishAttempt（工坊） |

| 平台 | Tenant、License、ContentPack、AuditLog、StageRun、AgentRun |

### 3.3 分镜核心字段

- **Shot**：order_key、display_no、duration{planned, measured}、beat_refs、purpose、camera{size, angle, movement：受控词表 + note}、cast[{character_id, appearance_variant_id, state}]、start/action/end 状态、`anchor_refs`（含版本）、`production_tier`（静帧运镜 / 首帧动画 / 全视频 / 对口型）、`shootability`{score, issues}、`camera_placement_id`、method_card_refs；不再用单一 segment_id 表示归属。
- **Segment**：一次生成素材段，可服务多个不相邻 Shot；purpose（如说话/反应/补拍）、target_mode、planned_duration、handles{head, tail}、priority（first / normal / backup）、`continuity_from`（接戏来源的具体素材版本）。
- **ShotTake**：shot_id、segment_revision_id、media_asset_id（含版本）、source_in/source_out、timeline_offset、audio_policy（keep / detach / mute）、可见说话状态、采用状态。一个镜头可拼接多个取用，同一素材区间可被不同镜头复用；所有采用均记录版本。
- **Keyframe**：position（start / end / intermediate）、offset、spec、所属镜头或素材段及 slot；候选存 KeyframeCandidate，采用后指向 MediaAsset。按模式能力选择首帧/首尾帧/多帧，不强制所有模式支持。
- **AudioCue**：kind（对白/旁白/音效/环境/音乐）、line_id 或 sound_intent、anchor{ref, edge, offset}、until 或 duration、mix、continues（跨集链接）。
- **DialogueLine**：kind（on_screen / inner_monologue / off_screen / narration），锁定状态；驱动声音与字幕。反应镜头盖画面时按 ShotTake/AudioCue 区间标为画外，不修改已锁台词。只有区间内可见的当面说话才要求口型。
- **锚点扩展**：Prop.physical_size（含单位）；场景变体的光线句及按轴线派生的正打/反打/站位全景；画风分锚点文本与画面文本；声音描述随版本锁定。DerivedView 引用根 AnchorVersion，不链式漂移。
- **Attempt / MediaAsset**：seed（可空，记录是否受支持）、参数快照、fail_reason、问题时间点、quality_tier（draft / upscaled / refined）、derived_from；升档及补段生成新素材，不覆盖原素材。

检查器分阶段运行：规划阶段允许尚无素材的取用意图；交付前每个采用镜头必须有完整有效取用。source_in/out 在素材实测时长去掉头尾余量后的区间内，按有理数时基换算；目标覆盖无缺口，变速须显式记录。分离音频连续、口型范围正确、关键帧槽位合法、升档素材已采用且有预算。改取用或素材版本重新检查覆盖与同步。

### 3.4 版本模型

- 每个内容对象有 ObjectRevision 链。
- ChangeSet：base_revisions、author（user / agent_run / system）、ops（add / replace / remove / split / merge / move）、status（candidate / adopted / rejected / conflicted）。
- 采用按范围（场 / 集 / 全剧）记录；锁作用于对象或字段，Agent 不得修改被锁内容。
- 冲突：触及对象的当前版本 ≠ base → conflicted，进入差异界面。
- 台词定稿单独锁定；改字必须先申请解锁。补段、升档或外部替换均提新候选，由 ChangeSet 原子切换相关 ShotTake；共享素材影响清单必须可见。

### 3.5 从 v0.3 迁移

v0.3 校验器的规则（重复 ID、悬空引用、场次归属、按目标覆盖、轨道重叠、素材哈希、就绪状态）全部改写为 `checkers` 单元测试；两个样例迁移为 fixture。

v2.1 扩展迁移按现有实际 schema 落地：旧 Shot.segment_id 转为明确取用记录，缺少素材/区间时标记待选片，不猜测采用；旧 dialogue/narration 声音类型需结合画面上下文确认。内容包与导出 schema 版本显式登记，禁止静默改变旧快照语义。

## 4. 多 Agent 体系

### 4.1 三层关系

```
Agent（角色：目标、判断、协作、返工决定）
  └─ 加载 Skill（方法包：方法论、规则、样例、方法卡）
       └─ 调用 Tool（读 IR / 提交 ChangeSet / 运行检查器 / 生成媒体 / 检索）
```

批量结构化产出（整集剧本、整场拆镜）由 Skill 驱动的结构化生成工具完成；Agent 负责规划、审视、修正。Agent 不能直接改已采用内容。

### 4.2 角色

| Agent | 职责 | 可写对象（只能提候选） | 首次上线 |
|---|---|---|---|
| 制片 | 任务树、排产、预算、出片档位默认值、闸门、日报 | Task、运行计划、档位建议 | 阶段 0 骨架，阶段 1 完整 |
| 资料研究 | 解析来源、StoryBible、热点精确归并与每日简报；1.5 增加相似归并与问答 | 故事库、TrendItem 映射候选、TrendDigest | 阶段 1 |
| 开发 | 五件套附配方、结构化分集地图、成本画像、原创开发、反同质化；1.5 生成选题卡 | AdaptationPlan、EpisodePlan、PlotUnit、AdaptationDecision、ShootabilityProfile；1.5 TopicIdea | 阶段 1 |
| 编剧 | 逐集剧本、台词本 | 剧本对象 | 阶段 1 |

### 4.3 协作规则

1. 层级调度：制片把整部作品拆成按集 / 按场的任务树分派。
2. 黑板：共享状态就是 IR；Agent 之间通过 ChangeSet、Issue、Task 交流，不靠对话传递正文。
3. 单写者：每类对象在每个阶段只有一个负责 Agent，其他只能提 Issue。
4. 制作-审查回路：最多 2 轮；仍不通过升级给人。
5. 并行：不同集、不同场并行；共享对象（如锚点）修改走冲突检测。
6. 人在回路：歧义发 Question 到收件箱；采用、超预算出片、发布必须人工确认。

### 4.4 运行时组件

| 组件 | 职责 |
|---|---|
| Agent 定义 | `agents/<role>/agent.yaml`：角色说明、可用 Skill、工具白名单、模型档位、预算、输出契约 |
| Agent 循环 | 思考 → 调工具 → 观察；步数上限；每步是 ADR-005 的持久化步骤 |
| 工具注册表 | schema（兼容 MCP）、权限范围、副作用等级（只读 / 提候选 / 付费 / 对外发布）、审批令牌 |
| 任务与消息 | Task 任务树、Issue（可定位到对象）、Question（问用户） |
| 上下文构建器 | 按任务范围取最小充分上下文；来源文本标记为不可信数据 |
| 预算与熔断 | 按 Agent / 任务 / 项目设 token、费用、步数上限 |
| 追踪 | 每步一个 span：输入摘要、工具、费用、产出 ChangeSet；可回放 |

安全：来源文本中的指令只当内容；高副作用工具需审批令牌；Agent 拿不到凭据明文，由模型连接层代调。

### 4.6 评测

## 5. 模型模式与出片工程

### 5.1 模型模式包

```
model-modes/<mode-id>/
  mode.yaml          类型（llm/image/video/tts/lipsync）、能力档案、成本模型、连接器类型
  compiler/          提示编译器（该模型的官方写法）
  connector/         连接参数模板（ComfyUI 工作流 JSON / API 请求模板）
  quality.json       历史通过率、常见失败类型（由选片数据回填，本地）
```

能力档案字段：时长范围、参考图数量上限、首帧/尾帧支持、原生音频、口型、画幅与分辨率、并发上限。可拍性规则和档位分配直接读取能力档案。

v2.1 补充：提示词软/硬长度限制及计量单位，参考数量/排序与输入图像音频槽位，长提示词并发约束、超时、题材偏置、分主体否定写法、语境化合规改写建议。每项标注来源、模式版本、验证状态和本地评测记录；OnlyShot 通过率和 H3 槽位数只是对应模式待复测经验，不能成为全局常量或绕过内容审核的规则。

提示编译分锚点图、分镜首帧、视频三层，身份冻结于参考，文本表达动作/表情/机位/光线；中性平光不泄漏至戏剧首帧。按视觉重要性排序参考；单场景图规则和槽位仅在声明支持的模式中启用。关键节拍增加首尾帧和候选数建议，受模型能力与预算约束。

### 5.2 连接器

| 连接器 | 机制 |
|---|---|
| ComfyUI | 工作流模板（API 格式）+ 参数映射；`POST /prompt` 提交，WebSocket 收进度，`/history` 取结果，`/view` 下载；多节点负载均衡与健康检查 |
| 中转 API | 异步提交拿任务 ID → 轮询或回调取结果 |
| 官方 API | 按厂商适配，统一成异步任务语义 |
| LLM | OpenAI 兼容接口 + 国内厂商接口；结构化输出 + 修复重试 |

### 5.3 生成队列语义

- 入队时锁定模型模式、画风锚点版本、画幅；之后改设置不影响已入队任务。
- 每个任务有幂等键；超时后先向远端对账，再决定重试，杜绝重复付费。
- 迟到的结果归档到它原来的候选，不覆盖当前采用版本。
- 每个模型连接有并发上限；队列按制片设定的优先级调度；重启续跑。
- 退出码、任务 ID 或“提交成功”都不足以判定产物成功：确认远端终态、下载文件、探测媒体参数和校验和后再入库。缺任务 ID 时先查远端列表；无法唯一匹配则暂停人工对账，不盲目重提。
- 失败按长度/内容审核/限流/网络/卡死/结果异常分类，保留上下文与建议；可重试故障与需调整输入区分。连续两次失败停止同段原样重抽，进入修补或人工选择；网络未知结果先对账，不当作已失败。

### 5.4 通告单排产

批次键 = 场景变体 + 出场演员造型 + 画风 + 模型模式。同批连续提交，提升一致性和模型缓存命中。

### 5.5 混合档位与漫剧渲染

| 档位 | 实现 |
|---|---|
| 静帧运镜（漫剧档） | FFmpeg：推拉摇移、缩放、震屏、闪白、速度线、转场；ASS 字幕；与配音对齐 |
| 首帧动画 | 关键帧 → 图生视频模式 |
| 全视频 | 文生 / 多参考视频模式 |
| 对口型 | 配音 + 画面 → 口型模式（仅支持的模型） |

制片 Agent 按节拍重要性（钩子、爽点、反转）和预算给出默认档位；用户可逐镜修改；修改后成本预估实时更新。

质量档 `draft | upscaled | refined` 与上述出片方式正交。估算按“全集草稿 + 已选区间升档 + 重试/补段”计算，同段复用不得重复计费；升档受采用与预算闸门控制。调提示词默认固定 seed（模式支持时），新候选才改 seed。关键段先跑，反应镜头包列为备用并受预算约束，不固定每场必跑数量。

### 5.6 接戏链与声音先行

- 接戏：用 FFmpeg 抽上一段尾帧；目标模式支持首帧时作为下一段首帧，不支持时作为参考图。
- 声音先行：先按声音锚点生成全部对白 → ffprobe 实测时长 → 按锚点重排时间 → 决定段长 → 再出画面；支持口型的模式最后对口型。
- 口型仅处理可见当面对白；内心独白约束嘴唇不动，画外音/旁白不指定画内说话者。长台词跨反应镜头时音轨连续，字幕样式按声音语义和区间生成。

### 5.7 热点雷达工程

完整协议见 [热点雷达设计](../product/trend-radar.md)，以下为实现约束：

1. **统一入口**：HTTP `POST /api/v1/intake/signals`、MCP `camery.submit_trend_signals`、JSON/CSV 文件适配到同一应用服务；schema 为 `camery.trend-signal/v1`。来源 URL、采集时间、采集器、数字口径必填；概要 ≤500 字、引用 ≤100 字；批次默认最多 500 条，逐条返回 accepted/duplicate/rejected 与字段原因。
2. **鉴权和幂等**：令牌哈希存储，绑定 tenant/collector/允许平台，可撤销；collector 不能靠请求体冒认。HTTP/MCP/文件同样检查权限、限流、审计。幂等键在租户和采集器内唯一；相同键不同请求哈希报冲突，相同请求重放原结果。可选 HMAC 不代替令牌鉴权；dry_run 只校验，不写业务数据、不消费幂等键。
3. **观测与归并**：不可变 TrendSignal 保存采集批次及来源。platform+external_id 或规范化 URL 用于识别 TrendItem；同条目新采集时刻/排名保留观测，重放不重复入库。部分拒收不丢弃有效条目；不得跨租户去重或泄漏结果。
4. **每日简报**：持久化定时器按租户时区运行，tenant+日期+配置版本幂等，失败可续跑；1.0 用平台/榜单内规则排序，来源/日期/覆盖范围随简报入制片收件箱。缺 7 日历史不算势头，数据不足不判蓝海；默认超过 30 天标过期，无新数据和采集器连续 2 天未推送单独提示。
5. **反同质化**：立项和剧本与近 30 天条目比对，达到可配阈值（初始 3 部）输出相似位置、来源、不能沿用的机制与差异化建议；最终由开发/审片提出候选，人工决定。
6. **私有化**：1.0 支持内网直推/本地 MCP 和鉴权文件导入，外部采集调度留在用户工具。1.5 可选租户云端信箱，实例主动拉取，确认消费后保留 7 天删除；断网可重试，消费幂等，关闭中继后不影响离线运行。
7. **1.5 增强**：相似归并候选需人工确认；按平台/榜单/日期可比口径标准化热度、7 日势头、跨平台扩散、30 日饱和度、AI 适配、可信度，再给四阶段建议。保留公式/权重/证据；来源相关性与缺数须展示，采集器自评分不能当客观事实。TopicIdea 一键立项、题材/俗套库更新候选、来源问答和工坊科普热点在这一阶段交付。
8. **接入包**：schema、curl、最小 Node/Python 推送脚本、MCP 配置、采集指令模板、dry_run 示例、拒收排查与状态页。Muse 的接口未知，先提供通用文件映射，不承诺专属连接器。所有外部文本按不可信数据处理；来源 URL 只存引用，不由入口任意抓取；截图只存引用。

### 5.8 选片与修补

出片表记录段/尝试/seed/模式/时长/费用/结果/问题秒点/下一步。选片台支持 trim_usable、needs_patch；先改取用头尾，再截帧→修图→补短段，最后调整提示/参考或拆段重抽。补段成功后候选差异展示取用替换与影响镜头，不增加公司侧通用剪辑编辑器。视觉模型镜头医生仍在 1.5，MVP 先提供规则诊断和人工标注。

| R9 | 方法包质量无法度量 | 阶段 0 建评测 |

| R13 | 多 Agent 结果难复现 | 每步追踪 + 回放；只通过结构化对象交流 |
