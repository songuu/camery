## 0. 一页纸

**Camery 是以分镜为核心的 AI 内容创作系统，一个内核，两个工作台。**

| | Camery Studio（公司） | Camery 知识工坊（个人） |
|---|---|---|
| 一句话 | AI 剧组工作台：把小说、创意、图书变成**可继续生产的镜头** | 把图书和笔记变成**可直接发布的成品** |
| 输入 | 原创稿、一句话创意、现成小说、图书、笔记 | 图书、读书笔记、文章 |
| 交付 | 完整剧本 + 完整分镜 + 锁定的角色/场景/声音 + 已生成的镜头与配音 → 剪映 / PR / 达芬奇 / Audition 做后期 | 播客、讲解视频、竖屏短视频、小红书图文、长文 → 一键分发 |
| 用户角色 | 你是制片/导演，AI 剧组干活 | 你是作者，AI 编导替你做成品 |
| 主要形态 | 私有化部署，自带模型 | 云端 SaaS |

**共享内核**：分镜内核 · 锚点体系 · AI 剧组（多 Agent）· 模型模式（自带模型）· 质量闸门 · 成本引擎。

**招牌功能**

1. **AI 剧组**：编剧、导演、美术、分镜师、声音设计、场记各司其职，你可以 @ 任何一个成员，像管理真实剧组一样管理 AI。
2. **锚点宇宙**：同一个人、同一间屋、同一把剑，100 集不走样；演员和场景跨项目复用，沉淀成公司资产。
3. **先看后拍**：先出动态分镜和成本预估，确认后才花钱出视频；每个镜头按重要性选择出片档位。
4. **一份笔记，五种成品**（个人侧）。
5. **热点雷达**：Codex、GrokBot、Muse 等采集工具每天推送红果、NetShort、X 等平台的热点，进入每日简报、立项和反同质化检查。

**明确不做**：剪辑软件、调色、混音母带（公司侧交给现有后期软件）；公司侧不做分发；不自训基础模型。

## 1. 关键判断

### 1.1 为什么公司侧走 Reelbench 模式

- 后期已经饱和：剪映、PR、达芬奇、Audition 成熟且团队已经在用；视频、图像、TTS 模型也由大厂持续供给。
- 真正的空白是"中段"：**从一个故事，到一批角色一致、可控、可拍、可交接的镜头**。今天大多数团队靠散落的提示词、截图和表格维持项目。
- Reelbench 的口号正好击中这一点："每一步都有明确的数据、状态和下一步，不再靠散落的提示词维持项目"。
- 因此公司侧的产品边界是：**前期 + 出镜头**，交付给后期软件，不做后期。

### 1.2 Reelbench 模式拆解

| 层 | Reelbench 的做法 | 我们学什么 |
|---|---|---|
| 流程 | 导入小说或一句创意 → 大纲 → 角色/美术/剧本 → 分镜 → 出图出片；每步可改、可重来、可撤销；长篇分批导入、接着往下写 | 阶段化 + 结构化数据 + 每步可回退 |
| 质量 | 背后的 shuohao-skills 每个阶段都有脚本检查的质量闸门（大纲 14 项、美术 10 项、剧本 10 项、站位 8 项、分镜 18 项） | 确定性闸门先行，模型只判断该它判断的 |
| 一致性 | 角色正面锚点 → 派生大头、侧面、背面；场景东南西北 + 俯视；分镜和视频按机位挂对应参考；每张图历史版本可换回 | 锚点 + 派生视图 + 按机位选参考 + 版本 |
| 出片 | 自接 ComfyUI 或中转 API，文本/图/视频各选模型；排队并行、重启续跑；入队锁定模型、画风、画幅；提示词按所选视频模式的官方写法；相邻两段接着演 | 模型模式、入队锁定、接戏 |
| 部署 | 本机程序，项目、素材、key 不出本机；网页界面直连本机程序 | 私有化与数据主权 |
| 商业 | 永久授权按视频模式分三档（$139 / $259 / $459，交付源码、含更新）；云端版按点数；代理版可自建站 | 多形态售卖 |
| 局限 | 单人单机；Agent 依赖用户本机 Codex 会话额度；交付止于项目内的分镜与素材 | 我们的机会 |

### 1.3 Camery Studio 比 Reelbench 多做什么

| 维度 | Reelbench | Camery Studio 增量 |
|---|---|---|
| 使用者 | 个人创作者，单机 | 团队：角色权限、审批流、评论 @人 / @Agent、多项目制片看板 |
| 规模 | 单部小说逐集推进 | 整季/系列：分集地图、付费卡点、跨集伏笔账本、造型时间线 |
| Agent | 用户本机 Codex 跑 Skill | 内置 AI 剧组、多模型、可装公司风格包 |
| 模型 | 按档位开放固定视频模式 | 开放的模型模式注册表；模型能力反过来指导分镜设计（可拍性） |
| 省钱 | — | 动态分镜预演、成本预估与预算闸门、混合出片档位、通告单式排产 |
| 质量 | 闸门 + 人工 | 闸门 + 场记/审片 Agent + 镜头医生 + 选片数据飞轮 |
| 声音 | 台词本带音色提示 | 声音锚点、声音先行、音频剧场景 |
| 交付 | 项目内分镜与素材 | 剪映草稿、FCPXML、EDL、字幕、分轨、音频剧工程、备案材料、投流素材包 |
| 进入点 | 小说或一句创意 | 任意阶段进入：已有剧本、角色设计、分镜表都能接着做 |

## 2. 产品形态与商业模式

### 2.1 三种形态

| 形态 | 面向 | 模型 | 数据 | 收费结构建议 |
|---|---|---|---|---|
| 云端版 | 个人创作者、小团队（知识工坊主阵地；Studio 轻量版） | 平台提供 | 云端 | 免费额度 + 订阅含点数 + 按量 |
| 私有化版（Studio 主形态） | 短剧/漫剧公司、MCN、有声书公司 | 自带：ComfyUI 集群、中转 API、官方 API、OpenAI 兼容接口 | 不出公司内网 | 年费按席位 + 实施服务（环境与 ComfyUI 搭建、公司风格包定制） |
| 白标版（后续） | 平台、培训机构 | 自带 | 客户自管 | 一次性授权 + 维护费 |

### 2.2 对架构的硬要求

- 一套代码，两种部署档案：`cloud` / `private`。
- 私有化必须**一台服务器 `docker compose up` 就能跑**，并支持内网离线。
- 由此基础设施收敛为：PostgreSQL + 对象存储（可退化为本地磁盘）；**工作流引擎从 Temporal 改为基于 PostgreSQL 的自研持久化执行**。
- 模型模式注册表 + ComfyUI 工作流适配器是一级能力，不是插件附属品。
- 私有化版的数据飞轮只在客户本地闭环，不回传。

### 2.3 私有化版怎么交付（Q1 决策：不交付源码）

| 项 | 做法 |
|---|---|
| 交付物 | 容器镜像 + 一键安装脚本；内网客户提供离线安装包 |
| 授权 | 签名授权文件，写明客户、版本档、席位数、有效期、功能开关；支持离线激活，联网校验可选并有宽限期 |
| 版本档 | 团队版（有席位上限）/ 企业版（不限席位、公司风格包定制、单点登录、可选源码托管） |
| 程序更新 | 版本化发布，数据库自动迁移，可回滚 |
| 内容更新 | 方法包、模型模式包、画风包单独签名发布，不必升级程序即可获得新提示词和新模型（对应 Reelbench"提示词和画风的更新都包含在内"） |
| 源码托管 | 企业版可选：源码交第三方托管，约定条件（如停止服务）下释放 |
| 知识产权保护 | 授权协议约束 + 构建产物混淆 + 内容包签名加密；承认无法绝对防止提取，以合同为主 |
| 售前试用 | 云端演示沙箱：预置样例项目，客户不必部署即可试用全流程 |
| 实施服务 | 环境部署、ComfyUI 集群搭建、模型模式调优、公司风格包定制 |

## 3. Camery Studio：AI 剧组工作台

### 3.0 全流程

```
立项 ──► 剧本 ──► 选角定妆 ──► 导演分镜 ──► 先看后拍 ──► 片场出片 ──► 选片 ──► 交付
 │        │         │            │           │            │           │        │
改编评估  节拍剧本  AI 试镜      站位+机位图  动态分镜     通告单排产   快速选片  剪映草稿
分集地图  台词本    角色/场景锚点 镜头取用    成本预估     混合档位     粗剪预览  FCPXML/字幕
付费卡点  钩子闸门  造型时间线    可拍性提示  预算闸门     接戏/声音先行 镜头医生  备案/投流包
剧本圣经  合规预审  声音锚点      节奏条                  手动替换
```

每个阶段：AI 剧组产出候选 → 闸门检查 → 人在关键节点确认。任何阶段都可以回退重做，影响范围自动标出。

> 优先级标记：**MVP** = Studio 1.0 必备；**1.5** = 第二版；**后续** = 视验证结果再定。

### 3.2 剧本

| 功能 | 说明 | 学自 | 优先级 |
|---|---|---|---|
| 节拍流剧本 | 动作节拍与台词交替；开场 3 拍内必须有钩子（闸门）；按语速估时 | shuohao novel-script | MVP |
| 台词本 | 按角色汇总，直通声音锚点生成配音 | shuohao novel-script | MVP |
| 合规预审 | 出片前检查题材和台词敏感项，避免为违规镜头花生成费用 | 自研 | MVP |
| 剧本导入 | Word、Fountain、表格剧本直接导入并结构化 | 自研 | MVP |
| 多版本对比 | 同一集两种写法并排，局部采用 | 版本内核 | MVP |

- 首集五模块模板、卡点轮换、情绪曲线、伏笔回收、角色知情来源进入检查器。连续三集同类卡点、连续三集情绪强度低于 6 等是可配置的初始规则；主观判断由审片 Agent 提 Issue，保留人工豁免。
- 声音语义区分当面说、内心独白、画外音、旁白；只有画面内可见说话者才做口型。长台词盖反应镜头时保持声音连续，画外状态按取用区间标注。
- 台词定稿后显式锁定，下游修改须申请解锁；集末自动更新事实、知情、人物状态、伏笔四本账。

### 3.3 选角定妆（锚点）

| 功能 | 说明 | 学自 | 优先级 |
|---|---|---|---|
| AI 试镜 | 每个角色出 4–8 个候选形象并排比较，选中即锁定为锚点 | character-refs 的锚点思路 | MVP |
| 角色锚点 + 派生视图 | 正面全身锚点 → 大头、侧面、背面、细节；派生图只参照锚点 | Reelbench、character-refs | MVP |
| 造型时间线 | 从剧本识别换装、受伤、年龄变化，按集段生成造型变体 | 自研 | MVP |
| 场景锚点 | 正面 → 东南西北 + 俯视；时段/天气/损坏状态变体；无人场景底板 | Reelbench、novel-art | MVP |
| 道具锚点 | 关键叙事道具的锚点与状态变化 | novel-art 道具表 | MVP |
| 画风锚点 | 风格参考 + 参数，项目级锁定；换画风先出成本预估 | Reelbench 入队锁定 | MVP |
| 声音锚点 | 试音 → 锁定音色 + 情绪变体 + 多音字词典；克隆声音必须有授权记录 | 自研 | MVP |
| 失效追踪 | 锚点一改，自动标出受影响的派生图、分镜图和已生成镜头，附重做成本 | character-refs 的过期追踪 | MVP |
| 全局改动影响分析 | "女主第 20–30 集改短发"、"所有雨夜改暴雨" → 影响清单 + 成本 → 批量重做 | 自研 | 1.5 |
| 公司演员库 / 片场库 | 锚点跨项目复用；续集和系列剧直接调用，形成公司的虚拟演员阵容 | 自研 | 1.5 |
| 造型参考库 | 服装、发型、表情参考图，附提示词 | 赛博班底的思路 | 后续 |

落地规则：场次按轴线派生正打、反打、站位全景；模型模式声明输入槽位和场景图上限。道具记录真实尺寸，每场光线句、全剧画风句、角色声音描述按版本复用；派生图始终引用根锚点，避免连环漂移。剪影辨识、口头禅密度和设计防侵权检查放在 1.5，作为可配置建议。

### 3.4 导演与分镜（核心）

| 功能 | 说明 | 学自 | 优先级 |
|---|---|---|---|
| 导演阐述 | 每场的目的、情绪、视觉母题、观众应知道什么 | Toonflow directorPlan | MVP |

| 对话式修改 | "第 3 场改夜景"、"@导演 这场节奏太慢" | 自研 | MVP |
| 对标节奏 | 导入有权分析的参考片 → 镜头拆解统计（平均镜长、每分钟切数、景别分布）→ 作为节奏目标 | reelbench video-shots | 1.5 |
| 色彩脚本 | 整集每场一格缩略图，看色彩节奏 | 自研 | 后续 |

### 3.5 先看后拍

| 功能 | 说明 | 优先级 |
|---|---|---|
| 动态分镜 | 关键帧 + 临时配音 + 字幕 + 镜头运动 → 整集预演；确认后才进入出片 | MVP |
| 成本预估 | 按镜头档位 × 模型价格 × 历史重试率估算每集、每季费用 | MVP |
| 预算闸门 | 超出预算需制片确认；可设每集、每项目上限 | MVP |
| 混合出片档位 | 每镜选择：静帧运镜（漫剧）/ 首帧动画 / 全视频 / 对口型；制片 Agent 按镜头重要性和预算给默认值，人可改 | MVP |
| 质量档位 | 与出片方式独立：草稿 / 超分 / 精修；全集先跑草稿，只给已采用且选中的素材区间升档，更新费用与取用版本 | MVP |

**混合档位的价值**：爽点镜头用全视频，过场和对话反应用静帧运镜。同一部剧可以从纯漫剧一路调到全视频，成本可控，也覆盖 AI 漫剧市场。

**漫剧档（静帧运镜）进入 MVP（Q3 决策）**：
- MVP：在关键帧上做推、拉、摇、移、缩放；常用效果（震屏、闪白、速度线）；转场；配音和字幕对齐。
- 1.5：2.5D 视差（深度分层）、局部微动（眨眼、发丝、衣摆）。
- 漫剧档镜头和视频档镜头是同一种"镜头素材"，可以在同一集里混用，一起交付到剪映。

### 3.6 片场出片

| 功能 | 说明 | 学自 | 优先级 |
|---|---|---|---|
| 队列 + 续跑 | 图和视频排队并行，重启续跑；入队锁定模型、画风、画幅 | Reelbench | MVP |
| 通告单式排产 | 按"场景 + 演员 + 造型"分批出片，像实拍跳拍一样：一致性更好，模型缓存命中更高 | 实拍制片做法 | MVP |
| 接戏链 | 上一段尾帧作下一段首帧，持物、站位状态延续 | Reelbench"相邻两段接着演" | MVP |
| 声音先行 | 先生成对白配音，用实测时长决定段长；支持的模型做口型同步 | 自研 | MVP |
| 手动替换 | 任何镜头都能上传外部修好的图或视频替换，记录来源 | 自研 | MVP |
| 镜头医生 | 视觉模型检查脸崩、手部异常、穿帮、角色与锚点不一致，给出诊断和改法（调参、换参考、改镜头设计、拆镜） | 自研 | 1.5 |

MVP 增加失败分类器：区分长度超限、内容审核、限流、网络、卡死、结果异常，并给出缩短、合规改写、降并发或对账建议。模型经验随模式包版本管理，不把作者实测通过率当通用保证。调提示词默认固定 seed，换候选才换 seed；不支持 seed 的模式明确标注。关键段先跑，备用反应段按预算排产；按素材与模型能力推荐首尾帧、多帧或图生视频模式。

### 3.7 选片

| 功能 | 说明 | 学自 | 优先级 |
|---|---|---|---|
| 快速选片台 | 键盘操作：通过 / 打回 / 重拍 / 评分；候选并排，对照关键帧和锚点 | reelbench video-sync 的对照呈现 | MVP |
| 粗剪预览 | 按顺序播放已通过镜头 + 配音 + 字幕；只是播放器，不是剪辑器 | 自研 | MVP |
| 镜头档案 | 点任意镜头：对应台词、锚点版本、模型模式、参数、尝试次数、费用 | 版本内核 | MVP |
| 选片数据飞轮 | 每次通过/打回都记录镜头特征、模型、参数和原因 → 改进可拍性评估与提示编译 | 自研 | MVP 采集，1.5 应用 |

MVP 修补阶梯：**先剪头尾 → 截问题前帧、修图、补短段 → 调整方案后重抽**。选片结果增加“剪后可用 / 需补段”，出片表记录尝试、seed、模式、问题时间点和下一步；同段连续两次失败暂停原样重抽并请求调整。补段、升档产出新候选，保留原素材和取用历史。

### 3.8 交付

| 功能 | 说明 | 优先级 |

## 4. Camery 知识工坊：个人侧

### 4.1 流程

```
导入书/笔记 ─► 选题建议 ─► 知识梳理 + 事实核查 ─► 讲解稿 ─► 一份稿，五种成品 ─► 发布中心
                                                 ▲
                                    一句话修改（"第二段讲快了"）
```

默认全自动，只在讲解稿和成品预览两处请用户确认。

### 4.2 一份笔记，五种成品

| 成品 | 规格 | 去向 |
|---|---|---|
| 音频播客 | 单人讲述或双人对谈；分章节；shownotes 附出处 | RSS → 小宇宙 / Apple / Spotify；喜马拉雅 |
| 横屏讲解视频 | 16:9，章节化，以图解为主 | B站、YouTube、视频号 |
| 竖屏短视频 | 9:16，60–90 秒，3 秒钩子 | 抖音、视频号、快手 |
| 小红书图文 | 6–9 张知识卡片 + 正文 | 小红书 |
| 长文 | 带出处的文章 | 公众号、知乎 |

五种成品共用同一份讲解稿和事实核查结果，按各平台的原生习惯重新编排，不是简单的格式转换。

### 4.3 功能

| 功能 | 说明 | 学自 | 优先级 |
|---|---|---|---|
| 按书归集的笔记导入 | Kindle 标注、阅读 App 导出、Markdown / Obsidian、网页文章 | Booko | MVP |
| 选题建议 | "你的笔记里有 5 个值得讲的观点"，按独特性和受众兴趣排序 | 自研 | MVP |
| 事实核查 | 主张与出处对照；事实类必须有来源，观点类明确标注 | 自研 | MVP |
| 讲法选择 | 单人讲述 / 双人对谈 / 情景剧 | 自研 | MVP（情景剧 1.5，复用 Studio 能力） |
| 个人锚点 | 自己的声音（授权克隆）、IP 形象、视觉模板（字体、配色、片头） | 锚点体系 | MVP（声音、模板） |
| 图解引擎 | 概念卡、流程、对比、时间轴、图表；数字和标签精确受控 | 自研 | MVP |
| 一句话修改 | "换个更生活化的例子"、"结尾加一个问题" | AI 剧组 Copilot | MVP |
| 领域资质提醒 | 医疗、金融、法律类内容提示平台资质要求 | 自研 | MVP |

| 系列规划 | 一本书拆成 N 期，节目单 + 发布日历 | 自研 | 1.5 |
| 主题串讲 | 把多本书里同一主题的笔记串成一期 | 自研 | 1.5 |

### 4.4 发布中心

- 各平台原生包装：标题、简介、标签、封面、章节时间戳、出处。

- 每个成品自动带 AIGC 显式与隐式标识，发布时填写平台的 AI 内容声明。

## 5. 共享内核

### 5.1 锚点体系

| 锚点 | 内容 | 用在 |
|---|---|---|
| 角色 | 正面锚点 + 派生视图 + 按集段的造型变体 | Studio |
| 场景 | 正面 + 四方位 + 俯视 + 时段/状态变体 + 无人底板 | Studio |
| 道具 | 锚点 + 状态 | Studio |
| 画风 | 参考图 + 参数 + 绑定的模型模式 | 两侧 |
| 声音 | 音色 + 情绪变体 + 多音字词典 + 授权记录 | 两侧 |
| 主播 | 个人声音 + IP 形象 + 视觉模板 | 知识工坊 |

规则：
- 锚点有版本；每个派生物记录它来自哪个锚点版本。
- 锚点变化 → 自动标出受影响的派生物和镜头，并附带重做成本。
- 每个锚点显示被多少镜头使用，防止误删。

### 5.2 分镜内核

采用实施计划中的 IR v0.5 规划（相对时间、ChangeSet 版本、Rendition、对象级采用），本次扩展见实施计划第 3 章：

| 新增字段 | 用途 |
|---|---|
| `shot.anchor_refs`（含版本） | 一致性与失效追踪 |
| `shot.production_tier` | 混合出片档位 |
| `shot.shootability` | 可拍性评分与问题 |
| `shot.camera_on_map` | 机位在俯视图上的位置与朝向 |
| `segment.continuity_from` | 接戏链 |
| `shot.dossier` | 镜头档案（关联尝试、费用、来源） |
| `ShotTake` | 镜头引用素材段版本及具体素材的 in/out，支持非相邻镜头复用、分离音频与替代候选 |
| `Segment.handles / priority` | 头尾余量与先跑/正常/备用；不再以包含连续镜头定义生成段 |
| `DialogueLine.kind` + 取用区间声音状态 | 当面说 / 内心独白 / 画外音 / 旁白；驱动口型、提示与字幕 |
| `quality_tier` | 草稿 / 超分 / 精修，与出片方式独立，记录素材升档关系 |
| `PlotUnit / EpisodeStateSnapshot / GenreProfile` | 跨集情节、续写约束、题材规则；经验阈值随包版本配置 |

### 5.3 模型模式注册表

每个模型模式是一个可插拔包：

| 组成 | 内容 |
|---|---|
| 能力档案 | 时长范围、参考图数量、首尾帧、是否原生带声音、是否支持口型、画幅 |
| 提示编译器 | 该模型的官方写法（方言隔离在这里，不污染分镜） |
| 连接器 | ComfyUI 工作流 / 中转 API / 官方 API / OpenAI 兼容接口 |
| 成本模型 | 按张、按秒、按 token 计价 |
| 质量记录 | 历史通过率、常见失败类型（来自选片数据飞轮） |

接入一个新模型 = 新增一个模式包，分镜和锚点不用改。可拍性评估直接读取能力档案。

v2.1 模式包补充提示词长度（含计量单位）、参考图数量与排序、图像/音频槽位、并发与超时、题材偏置、常见失败和语境化合规改写建议；每条经验带来源、适用版本、验证状态。锚点图 / 分镜首帧 / 视频分层编译，身份由锚点冻结，行为由文本表达；中性锚点光线不覆盖戏剧光。具体模型限制只在对应模式包生效。

### 5.4 质量闸门

- **确定性闸门**：每个阶段都有可执行规则（借鉴 shuohao 的做法：大纲、剧本、站位、分镜分别有十几项脚本检查），先于模型审查运行，零成本、可复现。
- **审查 Agent**：场记查覆盖与连续性，审片查质量，问题可定位并回流给负责的 Agent。
- **人工闸门**：改编方案、锚点锁定、动态分镜、选片、发布。

审查按故事质量（审片）→ 连贯与知情（场记）→ 可拍性（制作）三轮组织。MVP 自写结构化规则库：分级俗套、起名黑名单、AI 剧作常见反模式、钩子/卡点/情绪与伏笔；输出位置、问题、观众影响、改法和连带影响。只检查文字时报告“剧本/分镜逻辑已检查”，成片质量须有实物检查证据。

### 5.5 成本引擎

预估（档位 × 价格 × 预期重试）→ 预算 → 实际 → 偏差，按镜头 / 集 / 项目 / 租户汇总。重试率是最关键的成本指标，展示在制片看板上。

### 5.6 数据飞轮

选片决定、人工修改、重试原因 → 可拍性评估、提示编译、方法包评测集。私有化部署的数据只在客户本地闭环。

### 5.7 热点雷达与公共入口

详细协议与接入方式见 [热点雷达设计](trend-radar.md)。外部工具负责每日定时采集，Camery 接收并按租户处理，不托管用户的采集账号。

- **统一协议**：`camery.trend-signal/v1`，HTTP `POST /api/v1/intake/signals`、MCP `camery.submit_trend_signals`、JSON/CSV 文件导入共用校验；来源 URL、采集时间、采集器必填，数字必须有口径。
- **入口控制**：每个采集器独立令牌，绑定租户和允许平台，可撤销；幂等键、限流、批次上限、逐条 accepted/duplicate/rejected，以及 `dry_run`。文件导入同样鉴权和审计。
- **数据流**：不可变原始 TrendSignal → 带来源列表的 TrendItem → 每日 TrendDigest；增强版再生成 TopicIdea。精确匹配识别同一条目，新时间的排名变化仍保留为观测。
- **1.0 产出**：规则排序简报每日进入制片收件箱，按租户时区调度，带来源、日期和近 30 天同质化提醒；无新数据明确提示。采集器状态页展示最近推送、拒收率，默认连续 2 天无推送提醒。
- **1.5 产出**：跨平台相似度归并，疑似匹配人工确认；平台/榜单内标准化后展示热度、势头、扩散、饱和度、AI 适配和可信度，再给蓝海/将红/红海/衰退建议。选题卡只借机制，题材档案和俗套库更新仍需人工采用。
- **私有化**：1.0 走内网 HTTP/MCP 或文件；1.5 可选云端中继，私有化主动拉取、按租户隔离、确认消费后保留 7 天删除；离线部署无需中继。
- **接入包与边界**：提供 schema、curl、最小推送脚本、MCP 配置、采集指令模板；仅收概要（≤500 字）、短引用（≤100 字）和元数据，截图只存引用。内容视为不可信数据；不自动访问采集器提交的任意 URL。Muse 的具体能力待核实，可先用文件方式。

### 6.2 交互方式

- **自动化档位**：全自动 / 关键节点确认（默认）/ 逐步确认。
- **@成员**：在镜头或台词上写"@导演 节奏太慢"，由对应 Agent 修改，结果以差异对比呈现，你决定是否采用。
- **剧组面板**：每个成员当前在做什么、在等谁、花了多少钱；可暂停、重派。
- **制片日报**：每天汇总进度、费用、需要你拍板的事项。
- **公司风格包**：上传公司剧本规范和镜头习惯，整个剧组照此执行。

### 6.3 不可越过的规则

- Agent 只提候选，不直接改已采用内容。
- 付费出片超出预算、发布作品，必须人工或预算授权。
- 小说、笔记里的文字一律当作内容，不当作指令。

## 9. 合规与版权（产品化）

| 项 | 产品做法 |
|---|---|
| 微短剧备案 | 自动生成备案材料包；备案状态挂在项目上（以广电最新要求为准） |
| 内容合规 | 剧本阶段合规预审，出片前拦截 |
| AIGC 标识 | 所有导出物默认带显式与隐式标识；**不提供去除 AI 标识元数据的功能** |
| 声音与肖像 | 声音克隆、真人肖像参考必须上传授权记录 |
| 改编权 | 来源授权状态不是"原创"或"已授权"时，禁止交付和发布 |
| 领域资质 | 知识工坊对医疗、金融、法律内容提示平台资质要求 |
| 生成服务备案 | 云端版使用已备案模型；私有化版由客户对自接模型负责，产品内给出提示 |
| 授权台账与标识校验 | 素材授权编号随交付包留档；后期成片可回写并验证标识，具体字段与适用格式须经阶段 0 原文核实 |
| 热点来源 | 保存来源、日期和采集方式；不接收整剧/全文，不提供绕过平台限制的采集；过期数据显式标注 |

调研引用的 2026 年微短剧条款、备案分类与 AIGC 字段均为待核实项，不直接转成产品强制规则；由阶段 0 法务/产品任务核对原文后配置。

## 10. 风险与待验证假设

| 假设 | 验证方法 | 不成立时的调整 |
|---|---|---|
| 公司客户更想要私有化 + 自带模型 | 访谈 8–10 家短剧 / 漫剧 / 有声书公司，做预售 | 先做云端团队版 |
| 剪映草稿是交付刚需 | 访谈 + 验证当前版本格式与兼容性 | 以 FCPXML / EDL + 素材包为主 |
| 漫剧档（静帧运镜）有大量需求 | 统计目标客户漫剧与视频剧的订单比例 | 只保留视频档 |
| 团队协作是付费点 | 对比单人工具与团队版的付费意愿 | 协作降为 1.5 |
| 个人用户愿为"一稿多发"付费 | 公测转化率 | 收敛到播客 + 短视频 |

| 风险 | 应对 |
|---|---|
| 模型迭代快 | 模型模式包隔离，新模型只加包 |
| 开源竞品免费（Toonflow、火宝） | 差异化放在团队协作、整季规模、质量闭环、后期交付、私有化服务 |
| 生成质量不稳 | 先看后拍、选片台、镜头医生、数据飞轮 |
| 外部格式变化（剪映） | 多格式交付，剪映导出做兼容性回归测试 |
| 合规政策收紧 | 合规能力集中在一个模块，规则可配置 |
| 参考经验样本小、适用模型变化 | 标注来源/版本/验证状态，经验参数可调，经本地评测后发布 |
| 热点缺数、过期或采集器中断 | 保留观测、展示覆盖范围与日期；数据不足不做趋势结论；告警不自动启动外部采集 |
