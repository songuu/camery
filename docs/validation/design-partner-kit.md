# T0.12 设计伙伴访谈与参与确认模板

日期：2026-11-16。依据：[实施计划T0.12及阶段0验收](../plan/implementation_plan_v2.md)、[产品方案v2.1第10章](../product/solution_v2.md)。状态：**模板准备完成，真实访谈0家，确认参与0家，授权样例0份**；本文件没有招募或联系任何人。

T0.12要求招募2–3家设计伙伴，阶段0验收至少2家确认参与。方案H1另提出访谈8–10家公司的研究范围：早期2家参与不等于完整市场假设已成立，两名同公司受访者也不算两家伙伴。访谈中的反例是有效结果，不为填满名额或维持既定方案改写回答。

## 适用对象与一次访谈的顺序

目标是实际制作短剧、漫剧或有声书的公司/团队，能说明近期真实项目、交接链路和部署约束，并指定制作负责人及后期/技术对接人。邀请名单、发送渠道与发送动作由产品负责人决定；本模板不授权外联、签约、收款、安装或上传客户素材。

建议一次访谈按以下顺序开展，问题均记录原答和证据，不先介绍预期答案：

1. 请沿最近一个已完成项目，说明从原稿到后期交付的实际步骤、参与角色、软件版本、交付格式和一次返工经过。记录项目时间窗口及哪些数据无法披露。
2. 在展示方案前，分别记录最费时的步骤、失败次数、当前替代办法，以及哪些成本有记录、哪些只是估计。不要把“觉得有用”换算成节省比例。
3. 按下表核对适用假设；公司访谈不代替个人用户公测。
4. 说明当前可演示范围：核心库、章节回放、API/worker本地容器已有证据；工作台、真实模型质量、剪辑器兼容性及一键产品部署仍需各自验收。不得将固定夹具演示成已交付产品。
5. 如对方愿参与，核对参与人、可投入时间、试点任务、环境、样例与用途范围，记录明确确认依据及下一步；未给出确认即保持待定。

## 五项假设与证据口径

| ID / 产品方案假设 | 中性问题与需要记录的事实 | 不能据此得出的结论 |
|---|---|---|
| H1 公司更想要私有化+自带模型 | 哪些数据必须留本地、谁规定；当前模型服务/本机GPU及维护人；比较私有化与云团队版各自可接受条件；由有采购职责者说明采购流程与意愿 | 单个制作人的偏好不等于公司采购承诺；愿试用不等于预售；没有硬约束不自动证明云端适合 |
| H2 剪映草稿是交付刚需 | 最近一次交接实际使用的软件及版本；必须继续编辑哪些轨道/字幕/特效；可否接受FCPXML/EDL+素材包、需要哪些手工修复；记录真实验收人 | 客户说“要剪映”不能证明草稿格式可写；本机格式验证也不能证明客户愿意采用。两类证据分别关联[T0.13](../delivery/phase0-import-report.md) |
| H3 漫剧静帧运镜需求充足 | 同一明确期间内漫剧/视频剧/有声书订单数、各自定义、总量、可披露程度及选择理由；原数和分母都保留 | 无分母、不同时段或少数口述案例不形成目标市场比例；0订单与缺数据分开；不从两家伙伴外推全市场 |
| H4 团队协作是付费点 | 最近一次多人修改/审批冲突如何处理；单人工具与团队方案的实际差别；谁采购、席位/预算如何决定、愿意为何种明确能力付费 | 多人参与不等于愿为协作付费；未验证的功能/价格不作为报价或承诺。记录对方表达的条件，不自行填价格 |
| H5 个人愿为“一稿多发”付费 | 产品方案指定以后续个人公测转化率验证；先保留渠道、有效试用/曝光定义、转化观察期和退款/重复用户口径待产品确认 | 公司伙伴的看法不能证明个人转化率；当前无公测分母/付费事件，不填转化率、不提前把此项标为已验证 |

每项结果使用`支持/反对/混合/信息不足/本次不适用`，并关联原答、事实或材料。汇总时同时列出反例和缺失，区分公司、受访角色、期间和素材类型。方案中“不成立时的调整”是待产品决策的选项，不由访谈模板自动修改已确认架构或范围。

## 样例接收与试点范围

复用[授权台账模板](../compliance/rights-ledger-template.md)，不另造“已授权”布尔项。取得材料不等于许可已经核验；未完成核对的样例不能被标成已获准生成、仿声或公开演示。

| 接收前需确认 | 记录内容 |
|---|---|

| 权利链与具体用途 | 提供方能授予哪些使用权；内部解析、模型处理、改编、声音/肖像、演示和发布分别记录，不相互推定 |
| 数据流 | 是否允许发送到具体模型供应商/地域、可访问角色及保存/删除条件；缺项先补证，不先上传 |
| 参与确认与许可的区别 | 伙伴参与确认单独计数；样例许可、收费生成批准、发布授权分别核对，不由其中一项替代其他项 |
