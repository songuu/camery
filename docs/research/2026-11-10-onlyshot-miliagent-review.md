## 0. 结论先行

两份参考都是"一个人 + Claude Skill 跑通 AI 短剧"的**实战经验包**，不是平台产品。它们的价值不在架构，而在**大量踩坑后沉淀的生产规则**。我们方案里很多模块（可拍性、模型模式、选片、审查、交付）目前只有骨架，这两份资料正好能把规则填进去。

最值得借鉴的 5 点（会改动核心设计）：

| # | 借鉴点 | 来源 | 对我们的改动 |
|---|---|---|---|
| 1 | **镜头 ≠ 素材段，多对多 + 剪辑取用** | miliagent | IR 改：一段素材可剪出多个不相邻镜头；生成次数少、镜头多 |
| 2 | **三种声音：当面说 / 内心独白 / 画外音** | miliagent | 台词类型三分，驱动口型、提示词、字幕样式 |
| 3 | **模型"失败知识"写进模型模式包** | OnlyShot | 能力档案增加字数上限、审核词替换表、参考图上限、并发限制、题材偏置；失败自动分类给改法 |
| 4 | **修补阶梯 + 清晰度档位** | miliagent | 穿帮先剪、再补帧、最后重抽；全集先用草稿档，只给选中镜头升档 |
| 5 | **剧作结构化 + 俗套库** | 两者 | 开头 5 类 / 卡点 6 类及轮换规则、伏笔配对、情绪曲线、题材配方抽离测试、分级俗套库，全部变成可检查的数据 |

## 1. 两个参考是什么

### 1.1 OnlyShot（A-cat-with-carrots/OnlyShot）

- MIT 许可，约 400 star，v0.7.0（2026-11-10 仍在更新）。
- 一个 Claude Code Skill：一句想法 → 市场情报 → IP 简报 → 剧本 + 节拍地图 → 设定圣经 → ref 图库 → **分镜图（视频首帧）** → 视频段（即梦/Seedance）→ 自动初剪（字幕 + AI 标识）→ 上线前合规检查。
- 特点：每一步落成文件；大量量化规则（36 格 × 4–10 秒变奏、prompt ≤1500 字、ref 80–150 张）；沉淀了 17 种即梦失败模式；有 `--dry-run` 预估积分。
- 实测成本参考：一集 193 秒约 2,230 积分（约 ¥160），分镜图 108 + 视频 2,120（作者 2026-05 数据，未独立验证）。

### 1.2 miliagent.com（Miller，一人公司博客）

首页是个人笔记，短剧相关内容在[资料库](https://miliagent.com/library/)：

| 资料 | 内容 |
|---|---|
| AI 短剧技能包（3 个 Skill） | 剧本 → 分镜/资产/H3 提示词 → 在 RunningHub 上用 MiniMax H3 出片、修穿帮、出剪映剪辑单 |
| AI 短剧剧本技能包（3 个 Skill） | 短剧总编剧（总盘 → 分集）、电影短片编剧、剧本分镜 H3 版（含 9 份方法参考） |
| H3 工作流导入包 | ComfyUI 工作流：9 图片框 + 3 音频框，三种模式（参考生视频 / 首尾帧 / 数字人），固定 seed |
| 光影与镜头速查 PDF | 25 页：光的 4 维度、三点布光、景别、机位、9 种运镜、翻车速查（本次未细读） |

特点：**非常务实**，围绕"少抽卡、少穿帮"设计每条规则；明确区分镜头与素材段；把声音类型、站位、光线句、声音描述做成全剧锁死的文本。

### 1.3 许可与使用边界

| 资料 | 许可 | 我们怎么用 |
|---|---|---|
| OnlyShot | MIT | 可学习、可改写借鉴，保留版权声明 |
| Miller 技能包正文 | 未声明许可（免费下载 ≠ 开源授权） | **只学方法，不复制文本** |
| Miller 包内引用的上游 | MIT：GongLingRui/screen-creative-skills（Short Drama Script）、漫剧老李 Short-Drama Director | 可作为下一轮调研对象 |
| Sonilo（OnlyShot 可选配乐） | 第三方付费服务，免费档非商用，成片需上传 | 不内置；最多作为可选连接器 |

### 1.4 数据可信度

- OnlyShot 的数字大多来自作者自己两个项目（样本小），"97% 规则"无出处，部分文件互相矛盾（36 格 vs 60 格 × 3 秒）。**只能作为可调的默认值，不能写成硬规则。**
- 两者引用的 2026 年监管条款（AI 微短剧分类、《微短剧发展管理办法》2026-09-01 起每集 AI 标识、按投资额分类备案、"凡播必审"）和 AIGC 元数据字段名（来自 CSDN 博客）**需要法务按原文核实**后才能写进产品规则。

## 2. 借鉴清单（按对我们架构的影响排序）

### A. 镜头与素材段解耦：覆盖式拍摄（miliagent）⭐ 改 IR

**他们的做法**
- 镜头（分镜表 S01…）= 观众看到的一刀，1–6 秒；素材段（段01…）= 一次生成，5–15 秒。
- 先按"观众要看什么"拆镜头，再按"怎么少跑几次"把镜头归到素材段。一段可供多个**不相邻**镜头（例如"段03 供 S03、S16、S21"）。
- 对话戏：说话人一段（整句台词，固定近景），听者另跑一段不说话的反应；剪辑时交替切。
- 每段头尾各留 0.5–1 秒余量；每个镜头必须能在某段里找到"第 a–b 秒"，找不到就是漏了。

**我们现在**：RenderSegment = 若干**连续** Shot，一个镜头只属于一个段。

**改法**
```jsonc
// 新增：镜头取用 —— 镜头从哪个素材段的哪一段时间取
{"shot_id":"S16","take":{"segment_id":"seg_03","in":4.5,"out":6.0},"audio":"keep|detach"}
// Segment 不再要求镜头连续；增加 handles（头尾余量）与 priority（先跑/正常/备用）
{"id":"seg_03","purpose":"listener_reaction","handles":[0.5,0.5],"priority":"first"}
```
- 检查器：每个镜头必须有取用；取用区间必须在段的有效区间（去掉余量）内。
- 选片台、剪映导出都按"取用"组装。
- 收益：生成次数显著减少；关键段先跑；反应段便宜可多跑。这正是实拍的"主镜头 + 补拍"逻辑。

### B. 三种声音类型（miliagent）⭐ 改 IR

- 剧本阶段就区分：`当面说`、`内心独白`（嘴唇闭合不动）、`画外音`（画面里没人张嘴）。标错一种就会口型穿帮。
- **改法**：DialogueLine.kind 从 dialogue/narration 扩为 `on_screen | inner_monologue | off_screen | narration`。
  - 编译器：自动写入"嘴唇闭合不动 / 画面里没有人张嘴"。
  - 口型档：只对 `on_screen` 做口型。
  - 字幕：内心独白用单独样式（OnlyShot 用淡黄色，Miller 建议换色或加括号）。
  - 长台词切到听者时，后半句自动转为 `off_screen`（接上句）。

### C. 模型模式包的"失败知识"（OnlyShot）⭐ 改模型模式包

OnlyShot 17 种失败模式里，第 14–17 条和几条附带规则对我们最有价值。能力档案（`mode.yaml`）补充以下字段，并由选片数据持续回填：

| 字段 | 例子（即梦 5.0，作者实测，需我们自己复测） |
|---|---|
| prompt 长度通过率曲线 | <1300 字 100%；1500–1600 约 70%；>1700 为 0 → 软上限 1400、硬上限 1500 |
| 审核词替换表（分语境） | sinister→moody、"dark X"→"deep X"、blush→rose tint；描述角色比描述物件更容易触发 |
| 每帧参考图数量 vs 一致性 | 1 张约 95%，2 张约 80%，3 张以上低于 50% |
| 并发与长 prompt | 长 prompt 并发会失败，必须串行；并发上限、超时、重试次数 |
| 题材/主体偏置 | 复杂古建筑拟人易出 chibi 人体，简单几何体稳定 → 前移到设计阶段提示 |
| 否定子句写法 | 每个主体单独写一句否定，复数合写无效 |
| 输入槽位 | H3 工作流：9 图片 + 3 音频；槽位分配规则（见 F） |

**失败分类器**：每次失败按 `fail_reason` 归为 长度超限 / 内容审核 / 限流 / 网络 / 卡死，各自给出自动改法（截短、替换词、降并发、重新对账）。这是"镜头医生"的前置能力，可以进入 MVP。

还有两条工程规则：
- **不信任退出码，以文件落盘为准**。
- **提交后检查队列状态，卡住就回查任务列表找回任务 ID**。这两条并入生成队列的对账逻辑。

### D. 提示词三层隔离（OnlyShot）

| 层 | 目的 | 光线/风格 | 参考图 |
|---|---|---|---|
| 锚点图（ref） | 身份证 | 中性平光、多视图、白底 | — |
| 分镜图（首帧） | 视频首帧 | 戏剧光、3 层景深、9:16 | 主角 1 张（双人 2 张） |
| 视频段 | 动起来 | 沿用分镜图 | 按模式上限 |

- 核心原则：**"引用参考图 = 身份冻结，文字 = 行为变量"**。有参考图时，提示词不再描述长相、服装，只写动作、表情、机位、光线。
- 锚点阶段的风格词（neutral/flat）**不得**带进分镜图阶段，否则会压平戏剧光。
- 分镜图 8 段模板（人物 / 背景 / 动作 / 场景 / 机位含焦段 / 光线 / 文字 / 风格）。
- 首帧 10 项检查（主角占画面 ≥40%、≥2 层景深、亮度反差、字幕安全区为底部 1/8……），可作为关键帧的自动检查项。
- 参考图按**视觉重要性**排序，第一张权重最高。

→ 我们的提示编译器按层输出不同模板；风格锚点分"锚点用 / 画面用"两套文本。

### E. 视频模式按素材自动选择 + 关键镜头首尾帧（OnlyShot）

- 有首尾帧 → 首尾帧模式；有多关键帧 → 多帧模式；有分镜图 → 图生视频（默认，约 80%）；都没有 → 多参考兜底。
- 爆点、反派、心声、卡点镜头必须锁首尾帧。
- 候选张数随节拍重要性变化：关键 4 张 / 标准 1–2 张 / 过场 1 张。
- **改法**：Keyframe 增加首/尾/多帧槽位；制片 Agent 按节拍重要性自动给出首尾帧和候选张数的默认值。与"混合出片档位"合并。

### F. 素材与锚点的落地规则（miliagent）

| 规则 | 改法 |
|---|---|
| 对话场景出三张：正打、反打、站位大全景 | 场景锚点在"四方位 + 俯视"之外，按场次的轴线自动派生正打/反打对 |
| 一段只喂一张场景图（按机位选），多张反而混乱 | 编译器硬规则 |
| 槽位分配：图1 = 本段主角身份板，图2 = 唯一场景图，图3 起 = 其他角色/道具/站位全景，音频 = 声音参考 | 模型模式包声明槽位，编译器按规则分配 |
| 道具写真实尺寸（"直径约 8 厘米，一只手能握住"） | 道具锚点增加 `physical_size` 字段，自动写进每段提示词 |
| 每场一句"光线句"、全剧一句"画风句"、每角色一句"声音描述"，原样复用 | 场景锚点增加光线句；声音锚点增加描述文本；画风锚点增加画风句 |
| 换装只在锚点上改一次，不在改过的图上连环改 | 已有规则（派生只参照锚点），补"禁止从派生图再派生" |
| 角色身份板：主像 + 背/侧 + 坐/蹲 + 3 个表情 | 派生视图模板 |

OnlyShot 补充：
- **剪影族撞车检查**：同屏角色的轮廓要能区分。剪影按几何族分类，同一族最多 4 个。
- **口头禅密度**：首集前 1 分钟至少 3 次，每集至少 3 次。
- **设计防侵权清单**：不借用已有 IP 的名字和造型组合、避开品牌色、不以真实公众人物做反派模型。

### G. 修补阶梯 + 出片表 + seed 策略（miliagent）⭐ 改选片/出片流程

**修补阶梯**（穿帮时按顺序）：
1. **能剪就剪**：问题只在头尾几帧 → 改取用区间。
2. **能补就补**：截出问题前一帧 → 用图像模型修好 → 以首帧（或首尾帧）模式只补这一小段。
3. **最后才重抽**：先改提示词或参考图，再换 seed；原样重抽大概率还是错。
4. 同一段连续失败两次 → 停下来换思路（拆短、换参考），不做第三次原样重抽。

**出片表**字段：段、第几次、seed、模式、时长、结果（通过 / 剪头尾可用 / 要补 / 要重抽）、问题在第几秒、下一步。

**seed 策略**：调提示词时固定 seed（才能看出改动是否有效）；想换一版才改 seed；记录满意版本的 seed。

**改法**
- DailiesDecision 的结果枚举增加 `trim_usable`、`needs_patch`，并记录问题时间点。
- 选片台提供"截帧 → 修图 → 从此帧补段"的一键流程。
- Attempt 记录 seed；"微调提示词"默认锁 seed。
- 失败原因表（每段长得不一样 / 场景跳变 / 人物瞬移 / 张嘴念心里话 / 道具忽大忽小 / 口型不对）作为镜头医生的规则初版。

### H. 清晰度档位：先草稿、后精修（miliagent）⭐ 改成本模型

- 省钱档（一采 640P）跑通全集并粗剪 → 只给**选中的镜头**超分到 1920 宽 → 交付级镜头再做二采。
- **改法**：在"出片档位"（静帧运镜 / 首帧动画 / 全视频 / 对口型）之外，新增正交的**质量档**：`draft | upscaled | refined`。
  - 成本预估按"全集草稿 + 采用镜头升档"计算。
  - 升档任务只对已采用的镜头开放。
- 配套做法：多角色先单人各试 5 秒；关键段先跑。

### I. 剧作结构化（两者）

| 结构 | 规则 | 改法 |
|---|---|---|
| 开头钩子 5 类 | 冲突 / 悬念 / 危机 / 身份 / 反差；3 秒内可见冲突，10 秒内交代主角要失去什么 | EpisodePlan.open_hook_type |
| 结尾卡点 6 类 | 生死悬念 / 信息揭一半 / 反击第一下 / 更大危机 / 身份逼近 / 选择题；**连续三集不重复** | EpisodePlan.cliffhanger_type + 轮换闸门 |
| 第 1 集五模块 | 0–3 秒暴击 → 主角是谁有多惨 → 冲突当众爆发 → 底牌露一角 → 最后 5 秒卡点；核心人物 ≤3，新名词 ≤2 | 首集模板 + 闸门 |
| 情节单元 | 第 2 集起一件事跨 2–5 集：起压 → 加码 → 反转 → 释放 → 新危机；相邻集时间连续 | PlotUnit 实体（跨集） |
| 伏笔配对 | setup 必须有 payoff，记录埋设集与回收集 | 已有 PlotThread，补"未回收"检查 |
| 情绪曲线 | 每集情绪强度 0–10，不允许连续 3 集低于 6 | 分集地图上的曲线 + 闸门 |
| 爽点落地 | "反派愣住了 / 下次收拾你"不算；必须是镜头里看得到的结果 | 审查规则 |
| 打脸三要素 | 反派占势 → 主角硬证据 → **旁观者态度反转**（最易漏） | 审查规则 |
| 题材配方 + 抽离测试 | 主轴 × 辅轴 → 碰撞产物 → 招牌桥段 → 易崩点；拿掉辅轴主线仍成立 = 只是贴标签 | 改编五件套增加"配方"一项，审片 Agent 执行抽离测试 |
| 季级引擎 | 什么冲突能每集产生新问题；每次解决付出不同代价；季终的选择 | 剧本圣经字段 |
| 长剧升级比例 | 前 15% 至暗 → 15–45% 初步反击 → 45–80% 直面核心反派 + 重大挫折 → 最后 20% 回收 | 分集地图模板（按比例，不按固定集号） |
| 节拍时间节点 | OnlyShot 每集 7 个时间节点（0–3 秒开场、约 30 秒爆点、约 60 秒小赢……） | **做成可配置的题材模板**，不写死（无可靠出处） |
| 角色知识要有来源 | 台词提到的事，前面必须演过或说过 | 已有 KnowledgeState，补自动检查 |

**题材流派档案 GenreProfile**（OnlyShot 7 流派）：节奏参数（每分钟爽点数）、写作规则、禁忌、视觉指纹；流派判定树；中途切换流派的代价提示；"真人难拍 = AI 优势"的题材建议（修仙、末世、玄幻）。

### J. 审查体系的规则库（两者）

- **俗套库（OnlyShot 反套路检测器）**：三级黑名单。一级扣 3 分（抱错孩子、失忆假死、隐藏战神……），二级扣 1 分（含烂名模板），三级只警告且每集最多 1 次。
  - 评分 = 10 − 3×一级命中 − 二级命中。
  - 输出命中位置和替换建议。
  - 致敬或反转需用户确认豁免。
  - 每季度更新。
- **起名黑名单（Miller）**：高频言情名、高频姓、高频字；主要角色姓氏互不相同。
- **AI 写剧本 13 个毛病（Miller）**：慢热、爽点没落地、剧情循环、万能兜底、金手指白给、反派降智、主角零代价、单集闭环、标签拼接、网文腔、水词、电视剧化、卡点同一模板。每条附"怎么认"和"怎么改"。
- **三轮审**：编剧轮（故事）→ 场记轮（连贯）→ 制作轮（能不能拍），正好对应我们的审片、场记、制作三个 Agent。
- **问题分级**：必须修 / 应该修 / 可选。**问题单格式**：位置、问题、观众会怎样、改法、连带要改。→ Issue schema 增加 `audience_impact`、`ripple`（连带影响）字段。
- **OnlyShot 7 维评分**：前 3 秒钩子、可预测性、同质化、爽点密度、人物辨识度、俗套程度、付费卡点强度。
  - 辨识度测试：把名字换成 A/B/C，还能分清谁在说话吗？
  - 评审口吻规则：不夸；大部分打 8–10 分说明没认真批评。
- 交付措辞：只看过文字就说"剧本/分镜逻辑已检查"，没看成片不说"成片没问题"——与我们"计划 ≠ 实物"的原则一致。

### K. 可拍性前移到立项（miliagent）

- AI 出片成本 ≈ 场景数 × 人物数 × 造型数 × 抽卡次数，**总盘阶段就要算**。
- 前 10 集核心场景控制在 3–5 个；每集核心人物不超过 3 个；每个角色先只做一套造型。
- 高风险元素清单：打斗、多人同框、手部精细动作、画面里要看清的文字、水与火 → 前几集少用；必须用就拆短段，先试 5 秒。
- 画面文字（名单、合同、手机消息）：先做成道具图，再从这一帧轻推，或在剪辑里放静帧。

→ 把"可拍性"从分镜阶段扩展到**立项与分集地图**：输出"AI 制作成本画像"（场景、人物、造型、高风险元素数量）和预算区间，作为立项闸门。原方案里"改编评估报告"排在 1.5，建议其中的可拍性部分提前到 MVP。

### L. 交付与后期衔接（两者）

| 项 | 做法 | 改法 |
|---|---|---|
| 剪辑单 | 每段保留第几秒到第几秒；长台词处在第几秒盖哪段反应镜头（**分离音频**，声音不断）；缺什么镜头；配乐分段（情绪、起止、对白处压低）；全部字幕按声音类型标注 | 剪映草稿与 FCPXML 导出实现：分离音频叠加、字幕按声音类型分样式、配乐 cue 表 |
| 反应镜头包 | 每个主要角色每场多跑 2–3 段 3–5 秒不说话的反应 | 制片 Agent 自动排入"备用"优先级；剪辑单自动调用 |
| 自动初剪 | 按顺序拼接、统一规格、无声段补静音、字幕规则（每行 ≤14 字、在标点处断行）、按**实际**时长累计时间线、输出清单（计划 vs 实际、缺失镜头） | 粗剪预览与动态分镜导出复用这些规则 |
| AIGC 隐式标识回写 | 剪映导出后元数据可能丢失 → 用 ffmpeg 不重编码重新写入，并用 ffprobe 校验 | 交付模块新增"标识回写与校验"小工具（字段以 GB 45438-2025 原文为准） |
| 授权台账 | 音乐、字体、音效、声音的商用授权编号留档 | 合规模块新增授权台账，备案材料包引用 |
| 配乐提示 | 风格 + 乐器 + 按画面事件锚定的能量曲线（"约 30 秒他踹门时"）；音效每段一个事件、写材质与动作、不写音量 | 从节拍地图自动生成配乐与音效 cue |

### M. 续写交接包与"四本小账"（miliagent）

- 四本小账：**事实**（世界规则、能力与代价）、**谁知道什么**（何时、通过什么得知、误信什么）、**状态**（位置、朝向、手里有什么、造型编号、伤）、**伏笔**（埋设集、观众在等什么、计划回收集）。
- 每集结尾更新"交接包"；还记录"最近一次改动影响到哪几集、哪些镜头和素材段"。
- **改法**：剧本圣经本来就有这些账，补两件事：
  1. **集末状态快照**自动成为下一集的开场约束；
  2. 交接包可导出、导入，方便外部编剧或其他工具接力。

### N. 立项前的市场情报（OnlyShot）

- 搜近期榜单 → 实际读 1–2 篇爆款拆解（具体情节，不是标签）→ 给 3 个差异化选项（蓝海 / 将红 / 红海 / 衰退）。
- **反同质化**：创意与 3 部以上近期爆款撞车时，提炼它们的公式，列出"不能这么写"，再给 2–3 个不同角度。
- 抓取失败时回退到内置数据，并**告诉用户数据日期**。
- **改法**：立项阶段可选的"市场情报"步骤。所有数据带来源与日期，过期提示；私有化环境允许关闭联网。建议放 1.5，MVP 先做"同质化检查"。

### O. 产品化的小点子

| 点子 | 来源 | 用法 |
