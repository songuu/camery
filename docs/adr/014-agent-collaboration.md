# ADR-014：层级调度、IR 黑板与审查回路

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

产品中的多角色协作需要保留可追溯正文与单一采用状态，避免聊天记录成为隐含业务状态。按照 [实施计划 v2.1 第 2、4 章](../plan/implementation_plan_v2.md)，采用层级调度 + 黑板（IR）+ 单写者 + 制作-审查回路。

制片拆解任务树，角色通过 ChangeSet、Issue、Task 协作。每类对象每阶段只有一个负责写候选的 Agent，其他角色提 Issue；不同集/场可并行，共享对象修改检测冲突。审查最多 2 轮，仍未通过则升级给人。

## 代价与边界

需要记录任务依赖、责任人、问题位置和回流状态。单写者不意味着可以跳过版本冲突检测；独立审片也不能依据纯文字签发成片质量结论。歧义发 Question，采用、超预算生成与发布保留人工闸门。

## 实施与验证条件

- T0.5、T0.9：任务树、候选、采用与角色权限可追踪；共享对象并发变更进入冲突路径，不能覆盖当前采用。
- T1.8：故事审片、连贯场记、制作可行性三轮审查的问题含位置、严重度、观众影响、改法及连带影响；两轮后升级机制生效。
- T0.9、T2.13：越权和单写者负向测试通过，助手路由后的改动只呈现候选，暂停与重派保留证据。
