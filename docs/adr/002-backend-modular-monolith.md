# ADR-002：NestJS / Fastify 模块化单体

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

Studio 首发面向私有化部署，既需要清楚的模块边界，也需要控制安装和运维依赖。按照 [实施计划 v2.1 第 1、2 章](../plan/implementation_plan_v2.md)，采用 NestJS、Fastify 适配器和模块化单体。

版本、持久化执行、Agent、方法包、模型模式以及后续业务模块按职责分层。API 和 worker 可以按进程角色启动，但不能因此绕过同一应用服务的权限、版本与审计规则。

## 代价与边界

单体内仍需要约束依赖方向，防止业务模块跨层访问彼此内部状态。框架依赖注入和 HTTP 错误映射带来维护工作；模块目录存在不等于职责已经隔离，也不构成应用可运行的证据。

## 实施与验证条件

- T0.1、T0.10：应用骨架启动、认证入口、tenant_id 和 RBAC 负向测试通过；非法请求返回有上下文的错误。
- T0.6、T0.9：worker 执行持久化任务，API 通过应用服务发起操作；不把 HTTP 请求生命周期当任务生命周期。
- 后续业务阶段：使用真实 PostgreSQL 的集成测试证明事务与模块协作；私有化 Compose 验证实际运行服务。
