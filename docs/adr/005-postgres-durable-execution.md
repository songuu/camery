# ADR-005：基于 PostgreSQL 的自研持久化执行

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

私有化要求单台服务器部署并支持离线，工作流不能引入与此边界不匹配的必需基础设施。按照 [实施计划 v2.1 第 2 章](../plan/implementation_plan_v2.md)，采用基于 PostgreSQL 的自研持久化执行，取代 v1.1 的 Temporal。

执行引擎包含任务表、步骤日志、租约、重试、定时、人工闸门信号和取消。队列原语可以使用成熟开源库；业务状态机、审批、预算和版本规则仍由 Camery 控制。

## 代价与边界

需要自行验证租约过期、竞争执行、取消与恢复。数据库事务不能把远端付费调用变成天然的“恰好一次”；必须用幂等键、持久化结果和远端对账处理未知结果，不能在超时后直接重提。

## 实施与验证条件

- T0.6：真实 PostgreSQL 集成与故障注入覆盖租约竞争、worker 中断、重试上限、定时、人工信号及取消。
- 在步骤执行中杀掉 worker，恢复从最后完成步骤继续；已完成步骤不得重复产生副作用。
- T0.7、T3.7：模型提交与回收使用幂等和对账，未知状态明确暂停或查询；重放日志不再次执行外部付费操作。
- T0.9：Agent 的模型与工具调用复用同一持久化步骤语义。
