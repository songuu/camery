# ADR-018：统一热点 HTTP / MCP / 文件入口

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

用户现有采集工具定时收集多个平台热点，需要统一推送入口，避免 Camery 与某个采集工具绑定。按照 [实施计划 v2.1 第 2、5.7 章](../plan/implementation_plan_v2.md) 与 [热点雷达设计](../product/trend-radar.md)，采用 `camery.trend-signal/v1`，HTTP / MCP / 文件共用应用服务与租户权限；采集定时在外部，简报定时在内部。

Studio 1.0 提供 HTTP `POST /api/v1/intake/signals`、MCP `camery.submit_trend_signals` 和 JSON/CSV 导入。每个采集器独立可撤销令牌，身份由认证决定；幂等键按租户和采集器隔离，逐条 accepted/duplicate/rejected，dry_run 不写业务数据或消费幂等键。

TrendSignal 保留不可变观测，精确归并到 TrendItem，新日期/排名保留；每日规则简报带日期、来源与覆盖范围进入制片收件箱。1.5 才加入相似归并、完整评分、选题池、来源问答与可选云端中继；疑似归并和题材规则更新需要人工确认。

## 代价与边界

三种入口需要一致的校验、鉴权、限流和审计，MCP 是真实外部适配任务，不能由 [ADR-015](015-internal-tool-schema.md) 的内部 schema 兼容替代。平台不托管外部采集账号、不绕过平台限制、不任意抓取提交的 URL。Muse 接口未核实，先支持通用文件映射。

概要、短引用、经验阈值和过期窗口按设计配置；缺历史不计算不存在的势头，覆盖不足不做市场阶段结论。私有化 1.0 可内网直推或离线导入，不依赖云端中继。

## 实施与验证条件

- T1.13、T1.15：三入口同批输入结果一致；非法租户、已撤销令牌、采集器冒认、幂等冲突、部分拒收和 dry_run 负向测试通过，接入包可实用。
- T1.14：不同日期观测保留；按租户时区的每日简报重启不重复投递，来源/日期/缺数/过期及采集器中断可见。
- 阶段 6：相似归并未经确认不生效；评分证据与公式可追溯；中继隔离、断网幂等消费和确认后 7 天删除可验证，关闭中继仍可离线运行。
