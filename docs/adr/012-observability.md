# ADR-012：OpenTelemetry 与脱敏诊断

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

多 Agent、长任务和外部模型调用需要定位失败与费用，同时私有化数据需要留在客户环境。按照 [实施计划 v2.1 第 2、4、7 章](../plan/implementation_plan_v2.md)，采用 OpenTelemetry；私有化默认本地日志与追踪，可导出脱敏诊断包。

每个模型/工具步骤记录输入摘要、工具、费用和产出的 ChangeSet，能够关联任务、Agent、版本与尝试。不将凭据明文交给 Agent，也不因调试方便默认外传客户素材或完整来源文本。

## 代价与边界

需要设计稳定的关联字段、诊断脱敏和本地保留策略。追踪存在不等于任务可恢复，恢复依据仍是持久化步骤与正式业务状态。脱敏必须验证实际导出内容，不能仅靠字段命名承诺。

## 实施与验证条件

- T0.9：跨制片、研究与工具步骤的追踪关联可查，成本与候选可定位；回放与真实调用明确区分。
- T0.7、T0.10：模型/认证错误记录有上下文且不泄漏令牌、密钥或跨租户数据。
- T4.5、T4.7：本地日志与追踪可诊断，导出包经过脱敏负向测试；私有化默认不回传数据，诊断导出由明确操作触发。
