# ADR-006：Zod、JSON Schema 与 ChangeSet

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

全量快照不足以支撑工作台的增量编辑、局部采用与并发修改。按照 [实施计划 v2.1 第 2、3 章](../plan/implementation_plan_v2.md)，采用 Zod 定义 IR 并生成 JSON Schema，使用对象级版本和 ChangeSet。

数据库是正式状态，JSON 分镜包是版本化快照。稳定身份使用 ULID，显示镜号独立；相对时间与顺序键推导开始时间。用户、Agent、系统和外部替换均通过 ChangeSet 修改，采用与锁单独记录。

## 代价与边界

对象引用、时间锚点、候选与采用必须一起校验，冲突不能靠全包覆盖消解。schema 通过只证明结构条件，不能证明文件、事实、艺术质量或后期软件接受。旧快照迁移不得猜测素材取用或声音语义。

## 实施与验证条件

- T0.3：IR v0.5 生成 schema；重复 ID、悬空引用、场次归属、目标覆盖、音轨重叠、素材哈希与就绪检查迁移为测试，两个 v0.3 样例迁移为 fixture。
- T0.4：顺序键、时长、锚点及拆并插移通过属性测试；规划与交付阶段使用相应的完整性闸门。
- T0.5：ChangeSet 应用不可就地破坏输入；基版本变化报冲突；锁定台词和范围不得绕过；采用具有明确作者与版本记录。
- 核心库覆盖率按阶段 0 的 ≥95% 门槛验证，不以生成 schema 或少量成功样例代替。
