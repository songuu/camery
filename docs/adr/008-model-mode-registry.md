# ADR-008：模型模式注册表

日期：2026-11-10。状态：**设计决策已确认，实施按任务验收**。

## 背景与决策

不同模型的输入槽位、提示写法、时长、声音与费用不同，模型变化不应污染通用分镜。按照 [实施计划 v2.1 第 2、5 章](../plan/implementation_plan_v2.md)，采用模型模式注册表，每包包含能力档案、提示编译器、连接器、成本模型和质量记录。

ComfyUI、中转或官方 API、OpenAI 兼容 LLM 都通过模式包接入。提示编译隔离锚点图、分镜首帧和视频三层；可拍性与档位分配读取对应能力档案，入队锁定模式与内容版本。

## 代价与边界

每种模式都要维护契约和真实冒烟。参考数量、并发、提示长度及失败经验必须带来源、适用版本与验证状态；调研中的通过率或槽位数不成为通用保证，合规改写也不用于绕过审核。

## 实施与验证条件

- T0.7：注册表骨架、OpenAI 兼容 LLM、ComfyUI 和一个中转 API 连接器具备录制/回放与错误路径测试。
- ComfyUI 测试节点实际使用模板出图；回放成功不能替代真实连接验收。
- T3.6、T3.7：并发上限、幂等提交、未知结果对账、产物落盘/媒体探测/哈希、迟到结果归档通过验证。
- 质量记录在私有化本地闭环；模式经验变化进入评测与版本发布，不自动改变已入队任务。
