# 认证与项目权限

阶段 0 的单租户服务端骨架，保留完整 `tenantId`。身份来自已验证的 opaque bearer 会话；请求体、查询参数和 `x-user-id/x-tenant-id/x-role` 不参与身份确定。PostgreSQL 存储及运行身份要求见 [POSTGRES.md](POSTGRES.md)。

## 权限矩阵

| 项目角色 | 读取项目 | 提交候选 | 审核候选 | 运行任务 |
|---|---|---|---|---|
| viewer | 是 | — | — | — |
| editor | 是 | 是 | — | 是 |
| reviewer | 是 | — | 是 | — |
| admin | 是 | 是 | 是 | 是 |

角色都是项目成员身份。项目管理员不自动获得其他项目或租户权限；未知角色、操作、重复项目授权及无成员身份均拒绝。权限检查只是服务入口的一层，候选采用仍必须经过版本内核的对象作用域、基版本、锁和审批检查。

## 会话边界

`AccessService({tenantId,store})` 捕获受信任部署租户和存储方法。`authenticate(authorization)` 只接收单一 `Bearer cmry_…` 头，向存储传递 SHA-256 哈希。身份及角色逐请求读取，脱离回调结果并冻结；解析拒绝访问器和稀疏数组，不执行 getter 或暴露原生错误。`signOut(principal)` 仅接收同一 service 实际验证出的身份对象，不能通过构造 JSON 冒认会话。

`issueSession({tenantId,userId,ttlSeconds},issuer)` 仅供受信任安装/管理流程使用，生成 32 字节密码学随机令牌，寿命 60–86400 秒。原始令牌仅在签发结果返回一次；存储器只接收哈希。不得将签发器或成员管理器直接挂到未认证 HTTP 路由，也不能将原始令牌记入日志、评测、任务日志或版本候选。

当前没有密码注册、浏览器登录页、Cookie 会话、OIDC 或自助签发端点。可信安装者负责初始化成员、安全交付首次会话和配置独立数据库运行身份；完整用户管理、审批 UI、授权席位、限流和发行安装器仍需后续实施。令牌是持有即授权的凭据；非回环环境需要部署层 TLS。数据库连接仅供内部宿主持有。

鉴权与项目角色是请求开始时的快照。之后发生的撤销或降级会影响下一次鉴权；本骨架不声称已开始的业务事务会被自动中断。后续采用/审批等写服务应在其事务边界再次检查授权，并继续执行既有域内约束。

## 验证

`pnpm --filter @camery/access test:coverage` 验证纯权限和会话服务；`pnpm test:access:local --coverage` 另跑真实 PostgreSQL 的隔离、撤销、角色变更及最小权限测试。数据库测试缺配置明确失败。源码四项覆盖率门槛均为 95%；数据库源码只在真实数据库命令中计入。
