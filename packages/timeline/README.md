# @camery/timeline

阶段 0 的纯时间线代数。无需数据库、网络或媒体进程；IR 校验器复用本库，避免界面、校验器与版本引擎各自维护一套时间计算。

```sh
pnpm --filter @camery/timeline test
pnpm --filter @camery/timeline test:coverage
pnpm --filter @camery/timeline typecheck
```

## 时间与锚点

`resolveTimeline(input)` 接受按 ID 关联的集、版本、场次、节拍、台词、镜头、声音轨和 cue，返回 `valid / issues / timelines`。各 timeline 由 `episode_id + rendition_id` 定位，`spans` 是从对象 ID 到区间的只读 Map。

- 每集从 0 开始。镜头按场次、镜头顺序键推算起止，实测时长优先于计划时长；集合物理顺序不决定播放顺序。
- 锚点引用本集、本版本的镜头、节拍、cue 或集边界。节拍时间是其画面或声音证据的包络，不能虚构节拍在镜头内部的精确秒点。
- 每个起点、终点分别建图，用迭代拓扑排序求解；循环报实际环内的源位置。5,000 条 cue 依赖链已有回归用例。
- 视频集长度为画面轨长度。纯音频集长度由不依赖集尾的声音终点推算；“持续到集尾”的底乐可以跟随主体，但不能独自定义未知集长。`target_seconds` 是创作目标，不作为实际集长的替代值。
- 检查 cue 正时长、集内范围、淡入淡出与轨道重叠。区间按半开区间处理，首尾恰好相接不算重叠。cue 内容所属集也需一致，防止跨集虚报覆盖。

时间在库内使用约分后的 `Rational { numerator: bigint, denominator: bigint }`；输入十进制秒精确转换，计算中不反复取整。展示或导出时用 `toSeconds`，按 IEEE-754 中点取偶舍入；不可表达的溢出或非零下溢显式报错。BigInt/Map 不是交换快照格式，正式状态继续保存顺序、时长和锚点，使用方不应直接把求解结果 JSON 化并回写 IR。

求解允许返回带问题的部分区间供诊断；`valid:false` 时不能作为可交付时间线。外部未知 JSON 应先经过 IR schema 校验，不能通过类型断言代替结构检查。实测时长仍是调用方提供的声明，本库不读取媒体验证这些声明。

## 编辑代数

`insertClip`、`moveClip`、`splitClip`、`mergeClips` 返回新序列，不修改输入；泛型保留业务字段。ID 由调用方提供，拆并的新 ID 不得复用任何当前活动 ID。合并要求目标唯一、相邻且顺序一致。

顺序键使用 ASCII base62 比较，数据库保存和排序也必须使用等价的二进制排序规则，不能使用地区语言排序。通常只为移动或插入项生成中间键；`A / A0` 等词法空间不足时确定性重排键，始终保留 ID。新项传入的顺序键是草稿，最终键由放置位置决定。

拆并同时保持计划时长和有效时长：已有完整测量不能丢弃，未测量不能被伪造为完整测量。混合已测/未测的合并若会丢失已知时长修正，报 `MEASUREMENT_CONFLICT`；需要先补齐测量或显式调整方案。

这些函数操作单条序列，不直接写数据库或修改 IR 其他引用。[T0.5 versioning](../versioning/README.md) 已将顺序键重排、拆并身份替代、相关锚点/取用变更一起纳入候选及原子域状态计算；调用方不能只替换镜头数组并留下悬空引用。版本、锁、审批和实际采用不属于本库，数据库事务仍需另外接入。

## 验证

测试包括确定性边界、不可变输入、错误引用/循环、嵌套音轨重叠、精确舍入、10,000 组编辑场景以及另 10,000 组按独立整数毫秒模型核对的双集/双版本时间推算。具体数量与覆盖率以 `pnpm check` 当前输出为准。
